# 行程詳情

> **目的**：看一趟行程每天的安排，並在這裡新增、修改、打卡、管理照片、批次處理項目、生成路線或刪除整趟行程。這是 App 功能最多的一頁。
>
> 本文件依 2026-10-16 的程式現況整理（as-is），描述的是「現在的行為」，不是新設計。跟直覺不同、還沒確定是不是刻意的行為，記在「待辦」。

## 行為規格

### Requirement: 讀取行程與項目 <!-- ADDED 2026-10-16 -->

進入行程詳情時，系統 SHALL 讀取該行程與它的所有項目。開始與結束日期都有填時 SHALL 顯示時間軸；只填一個或都沒填時不顯示。行程不存在時 SHALL 顯示「找不到行程」。讀取項目失敗時 SHALL 照常顯示行程，並顯示錯誤訊息。

#### Scenario: 讀取成功
- GIVEN 「京都大阪 5 日遊」（10/14–10/18）有 10/14 的「伏見稻荷」與 10/15 的「金閣寺」
- WHEN 使用者打開這趟行程的詳情
- THEN 標題顯示「京都大阪 5 日遊」，列表依日期列出兩個項目，讀取中狀態結束

#### Scenario: 日期沒填完整時不顯示時間軸
- GIVEN 行程只填了開始日
- WHEN 使用者打開這趟行程的詳情
- THEN 不顯示時間軸

#### Scenario: 找不到行程
- GIVEN 行程已被刪除
- WHEN 使用者打開這趟行程的詳情
- THEN 顯示「找不到行程」

#### Scenario: 讀取項目失敗
- GIVEN 讀取這趟行程的項目時發生錯誤
- WHEN 使用者打開這趟行程的詳情
- THEN 仍顯示行程標題，列表上方以紅字顯示錯誤訊息

#### Scenario: 讀取中
- WHEN 行程詳情正在讀取
- THEN 整頁顯示讀取畫面

### Requirement: 項目依日期分組、組內依時間排序 <!-- ADDED 2026-10-16 -->

項目列表 SHALL 依日期分組，日期早的在前。組內 SHALL 依時間排序（有抵達時間用抵達時間，沒有就用出發時間），沒排時間的項目排在當天最後；時間相同時維持讀取順序。

#### Scenario: 依日期分組
- GIVEN 行程有 10/15 的「金閣寺」與 10/14 的「伏見稻荷」
- WHEN 使用者打開行程詳情
- THEN 先列 10/14 組（伏見稻荷），再列 10/15 組（金閣寺）

#### Scenario: 組內依時間排序，沒排時間的排最後
- GIVEN 10/14 有「清水寺」抵達 14:30、「伏見稻荷」只填出發 09:00、沒排時間的「祇園晚餐」
- WHEN 使用者打開行程詳情
- THEN 10/14 組依序是伏見稻荷、清水寺、祇園晚餐

### Requirement: 選日期篩選列表 <!-- ADDED 2026-10-16 -->

時間軸 SHALL 有「總覽」與每天一個「第 N 天」，每天的地點名稱 SHALL 在一行內完整顯示（放不下時所有格子一起加寬，上限約 7 個中文字，超過才「…」）。選某一天 SHALL 只列出當天項目，並把列表捲到該天；選「總覽」SHALL 列出全部。重新讀取（例如刪除項目後）SHALL 保留目前選的日期。時間軸上每天的「(已完成/總數)」SHALL 以全部項目計算，不受目前選的日期影響。

#### Scenario: 選某一天
- GIVEN 行程有 10/14 的「伏見稻荷」與 10/15 的「金閣寺」
- WHEN 使用者點 10/15 那天
- THEN 列表只剩「金閣寺」

#### Scenario: 選總覽
- GIVEN 目前選的是 10/15
- WHEN 使用者點「總覽」
- THEN 列出全部項目

#### Scenario: 重新讀取後保留選的日期
- GIVEN 目前選的是 10/15，當天有「金閣寺」與「嵐山」
- WHEN 使用者刪除「嵐山」
- THEN 重新讀取後仍只列出 10/15 的「金閣寺」

#### Scenario: 時間軸計數不受日期篩選影響
- GIVEN 10/14 有 2 個項目、10/15 有 1 個項目，目前選的是 10/15
- WHEN 使用者看時間軸
- THEN 10/14 仍算 2 個、10/15 算 1 個

#### Scenario: 選日期時捲到該天
- WHEN 使用者點某一天
- THEN 列表自動捲到那一天

### Requirement: 標記完成 <!-- ADDED 2026-10-16 -->

項目的「⋮ → 標記完成／標記未完成」SHALL 立即反映在卡片上並存檔：標記完成時記下完成時間，標記未完成時清除完成時間。存檔失敗 SHALL 恢復原狀態並提示錯誤。時間軸上當天的「(已完成/總數)」SHALL 同時更新。

#### Scenario: 標記完成
- GIVEN 「金閣寺」未完成，現在是 10/15 10:00
- WHEN 使用者標記完成
- THEN 卡片立即顯示已完成，存檔時記下完成時間 10/15 10:00

#### Scenario: 標記未完成
- GIVEN 「金閣寺」已完成
- WHEN 使用者標記未完成
- THEN 卡片變回未完成，存檔時清除完成時間

#### Scenario: 標記完成存檔失敗
- GIVEN 存檔會失敗
- WHEN 使用者標記完成
- THEN 卡片先顯示已完成，存檔失敗後變回未完成
- AND 底部提示錯誤訊息

#### Scenario: 時間軸完成數跟著更新
- GIVEN 10/14 有「伏見稻荷」與「清水寺」，都未完成，時間軸第 1 天顯示 (0/2)
- WHEN 使用者把「伏見稻荷」標記完成
- THEN 時間軸第 1 天立即顯示 (1/2)，不用離開再進來

### Requirement: 展開項目卡片 <!-- ADDED 2026-10-16 -->

點項目卡片 SHALL 展開，顯示備註全文、時間資訊與照片；再點一次 SHALL 收合。可以同時展開多張。

#### Scenario: 展開與收合
- WHEN 使用者點「金閣寺」的卡片，再點「伏見稻荷」的卡片
- THEN 兩張都展開
- AND 再點一次「金閣寺」，只有「金閣寺」收合

### Requirement: 刪除項目 <!-- ADDED 2026-10-16 -->

項目的「⋮ → 刪除」SHALL 先確認「確定要刪除「{活動}」嗎？此操作無法復原。」，確認後刪除並重新讀取。刪除失敗 SHALL 提示錯誤。

#### Scenario: 確認後刪除項目
- GIVEN 行程有「伏見稻荷」與「金閣寺」
- WHEN 使用者刪除「金閣寺」並確認
- THEN 列表只剩「伏見稻荷」

#### Scenario: 刪除項目失敗
- GIVEN 刪除會失敗
- WHEN 使用者刪除並確認
- THEN 底部提示錯誤訊息，項目仍在

#### Scenario: 刪除前確認
- WHEN 使用者按「⋮ → 刪除」
- THEN 跳出確認視窗，按取消不會刪除

### Requirement: 刪除整趟行程 <!-- ADDED 2026-10-16 -->

「⋮ → 刪除行程」SHALL 先確認「確定要刪除「{標題}」嗎？這個動作無法復原。」，確認後刪除行程與它所有的項目，並回到行程列表；取消則不變。刪除失敗 SHALL 提示錯誤並留在這一頁。

#### Scenario: 確認後刪除行程
- GIVEN 「京都大阪 5 日遊」有兩個項目
- WHEN 使用者刪除行程並確認
- THEN 行程與兩個項目都被刪除，回到行程列表

#### Scenario: 取消刪除行程
- WHEN 使用者在確認視窗按取消
- THEN 行程不變，留在這一頁

#### Scenario: 刪除行程失敗
- GIVEN 刪除會失敗
- WHEN 使用者刪除行程並確認
- THEN 底部提示錯誤訊息，留在這一頁

### Requirement: 生成路線 <!-- ADDED 2026-10-16 -->

「⋮ → 生成路線」SHALL 先確認這趟行程排得出路線，排得出就進入這趟行程的路線頁。路線 SHALL NOT 另外存檔：路線頁打開時依行程當下的項目排出來，行程改了，下次打開就跟著變。行程不到兩個不同地點時 SHALL 提示「至少要有兩個不同的地點才能生成路線」。

#### Scenario: 生成路線成功
- GIVEN 京都行程有「伏見稻荷」與「金閣寺」兩個不同地點
- WHEN 使用者按「生成路線」
- THEN 進入京都行程的路線頁
- AND 沒有另外存一份路線

#### Scenario: 地點不足
- GIVEN 行程只有「金閣寺」一個地點
- WHEN 使用者按「生成路線」
- THEN 底部提示「至少要有兩個不同的地點才能生成路線」，留在這一頁

### Requirement: 新增項目時帶入日期 <!-- ADDED 2026-10-16 -->

當日摘要的「新增這天」與當天空狀態的按鈕 SHALL 進入快速新增，並預先帶入那一天。右下「＋」SHALL 進入新增項目，日期由使用者自己選。

#### Scenario: 新增這天
- GIVEN 行程是 10/14–10/18，目前選的是第 3 天
- WHEN 使用者按「新增這天」
- THEN 進入快速新增，日期預設 10/16

#### Scenario: 右下新增項目
- WHEN 使用者按右下「＋」
- THEN 進入新增項目，日期沒有預設

### Requirement: 管理項目照片 <!-- ADDED 2026-10-16 -->

展開的卡片 SHALL 有「新增照片」，從相簿挑一張加到項目；項目的第一張照片 SHALL 自動成為封面。照片可以「設為封面」或刪除；刪除封面照片時，項目變成沒有封面。新增、設封面、刪除失敗時 SHALL 提示錯誤。預覽畫面刪照片會先確認，縮圖選單刪照片不確認。

#### Scenario: 新增照片
- GIVEN 「金閣寺」沒有照片
- WHEN 使用者從相簿挑一張照片
- THEN 「金閣寺」有 1 張照片，並成為封面

#### Scenario: 新增照片失敗
- GIVEN 存照片會失敗
- WHEN 使用者從相簿挑一張照片
- THEN 底部提示錯誤訊息，照片數不變

#### Scenario: 設為封面
- GIVEN 「金閣寺」有照片 A（封面）與照片 B
- WHEN 使用者把照片 B 設為封面
- THEN 「金閣寺」的封面變成照片 B

#### Scenario: 刪除照片
- GIVEN 「金閣寺」有照片 A（封面）與照片 B
- WHEN 使用者刪除照片 A
- THEN 「金閣寺」只剩照片 B，沒有封面

#### Scenario: 按下新增照片開啟相簿
- WHEN 使用者按「新增照片」
- THEN 開啟相簿，可以挑一張照片

#### Scenario: 刪照片的確認
- WHEN 使用者在預覽畫面刪照片
- THEN 先跳出確認；從縮圖選單刪除則不確認

### Requirement: 選擇模式與批次操作 <!-- ADDED 2026-10-16 -->

「⋮ → 選擇模式」後，標題 SHALL 變成「已選擇 N 項」，點卡片勾選或取消勾選。底部工具列 SHALL 有刪除、標記完成、取消：刪除前先確認「確定要刪除所選的 N 個項目嗎？此操作無法復原。」；完成後 SHALL 提示「已刪除 N 個項目」或「已標記 N 個項目為完成」、離開選擇模式並重新讀取。取消 SHALL 清空勾選並離開選擇模式。

#### Scenario: 勾選項目
- GIVEN 已進入選擇模式
- WHEN 使用者點「伏見稻荷」與「金閣寺」，再點一次「伏見稻荷」
- THEN 標題顯示「已選擇 1 項」，只勾著「金閣寺」

#### Scenario: 批次刪除
- GIVEN 選擇模式勾選了「伏見稻荷」與「金閣寺」，行程另有「嵐山」
- WHEN 使用者按刪除並確認
- THEN 兩個項目被刪除，列表只剩「嵐山」
- AND 提示「已刪除 2 個項目」，離開選擇模式

#### Scenario: 批次標記完成
- GIVEN 選擇模式勾選了「伏見稻荷」與「金閣寺」
- WHEN 使用者按標記完成
- THEN 兩個項目都變成已完成
- AND 提示「已標記 2 個項目為完成」，離開選擇模式

#### Scenario: 取消選擇模式
- GIVEN 選擇模式勾選了「金閣寺」
- WHEN 使用者按取消
- THEN 清空勾選並離開選擇模式

#### Scenario: 批次刪除前確認
- WHEN 使用者在選擇模式按刪除
- THEN 跳出確認視窗，按取消不會刪除

## 技術設計

### 資料來源

| 用途 | 使用的 use case |
|---|---|
| 讀取行程 | `GetItineraryUseCase` |
| 讀取項目 | `GetItemsByItineraryUseCase` |
| 分組與排序、依日期篩選 | `GroupItemsByDateUseCase`、`FilterItemsByDateUseCase` |
| 標記完成 | `UpdateItineraryItemUseCase` |
| 刪除項目、刪除行程 | `DeleteItineraryItemUseCase`、`DeleteItineraryUseCase` |
| 生成路線 | `GetRouteForItineraryUseCase`（先排一次確認排得出來；路線頁打開時用同一個 use case 依行程再排一次） |
| 照片 | `AddPhotoUseCase`、`DeletePhotoUseCase`、`SetCoverPhotoUseCase`、`GenerateThumbnailUseCase`（新增後在背景產生縮圖） |
| 批次刪除、批次標記完成 | `BatchDeleteItemsUseCase`、`BatchUpdateItemsUseCase` |

### 畫面與狀態

- `ItineraryDetailScreen` 在 `LaunchedEffect(itineraryId)` 送 `LoadItinerary`。
- `groupedItems` 是套用日期篩選後的分組，給列表用；`allGroupedItems` 是全部項目的分組，給時間軸計數用。
- 標記完成、新增照片、設封面、刪照片不重新讀取，直接更新 `groupedItems` 與 `allGroupedItems` 裡的那一項；刪除項目、批次操作會重新讀取。（2026-10-16 修正：原本只更新 `groupedItems`，時間軸完成數不會變。）
- 標記完成時的完成時間與修改時間取自 Koin 注入的 `Clock`（正式執行給手機時鐘，測試給固定時鐘），比照今日頁；這頁只用到「現在的時刻」，不需要時區。
- 刪除項目、刪除行程、批次刪除的確認視窗由畫面控制；刪除行程成功後 ViewModel 送 `NavigateBack`。
- 「新增這天」送 `QuickAddItem(dayIndex)`，ViewModel 換算成「開始日 + dayIndex」，超出範圍時夾在開始日與結束日之間，再送 `NavigateToQuickAddItem`。
- ViewModel 另有依標籤篩選（`FilterByHashtag`）與全選（`SelectAll`），畫面都沒有接上；依標籤篩選也只做了一半（切換日期或重新讀取會洗掉標籤篩選）。2026-10-16 決定兩者都刪除（含只給它用的 `FilterByHashtagUseCase`），之後有規劃再照規格重做。
