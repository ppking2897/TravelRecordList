# TravelApp UX 改善建議

> 分析日期：2026-04-09
> 基礎：程式碼現狀 + 同類 App 競品對比

---

## 一、現有 UX 流程分析

### 1.1 新增行程流程

```
首頁 → 點擊 + 按鈕 → 新增行程表單 → 儲存 → 跳轉至行程詳情
```

| 步驟 | 動作 | 評價 |
|------|------|------|
| 1 | 點擊 TopAppBar 右上角的 + 按鈕 | 位置合理，但按鈕只有 32dp (IconSize.lg)，偏小 |
| 2 | 填寫表單（標題、描述、開始/結束日期、封面照） | 欄位數適中，有草稿自動儲存 |
| 3 | 點擊「儲存」 | 儲存後清除 backStack 跳到詳情頁，合理 |

**問題**：
- 新增按鈕是 `Surface` + `MaterialTheme.shapes.small`（方形），不是圓形的 FAB，不符合 Material3 常見的新增互動模式
- 新增按鈕顏色用 `tertiary`（深藍色），而非 `primary`（橙色），視覺上不直覺

### 1.2 新增行程項目流程

```
行程詳情 → 點擊 FAB → 新增項目表單 → 儲存 → 返回詳情
```

| 步驟 | 動作 | 評價 |
|------|------|------|
| 1 | 點擊 FAB（+） | 標準 Material3 互動 |
| 2 | 填寫活動、地點、日期、時間、照片、備註 | 欄位較多，需要捲動 |
| 3 | 儲存 | 返回上一頁，合理 |

**問題**：
- 表單欄位較多（活動、地點名稱、地址、日期、到達時間、離開時間、照片、備註），一次填寫可能令人疲憊
- 沒有分步引導或「必填先填、選填稍後」的區分
- 日期欄位：若行程未設定日期範圍，會顯示「請先在行程中設定日期範圍」的 disabled 欄位，使用者可能困惑需要先返回編輯行程

### 1.3 編輯後返回體驗

| 場景 | 行為 | 評價 |
|------|------|------|
| 編輯行程後儲存 | `backStack.removeLastOrNull()` 返回上一頁 | 合理 |
| 編輯項目後儲存 | `backStack.removeLastOrNull()` 返回上一頁 | 合理 |
| 新增行程後儲存 | 清除 backStack 跳到詳情頁 | 合理，但返回鍵會直接回首頁 |
| 按返回鍵未儲存 | 直接離開，無確認提示 | 有問題：可能遺失已輸入的資料 |

### 1.4 導航深度

```
首頁 → 行程詳情 → 編輯項目      (3 層)
首頁 → 行程詳情 → 地圖 → 編輯項目 (4 層)
首頁 → 行程詳情 → 新增項目        (3 層)
首頁 → 旅遊歷史                   (2 層)
```

導航深度控制在 2-4 層，合理。

### 1.5 錯誤處理和使用者回饋

| 畫面 | 儲存成功回饋 | 錯誤回饋 | 評價 |
|------|-------------|----------|------|
| 新增行程 | 無 toast/snackbar，直接跳頁 | inline 紅字 | 成功回饋不足 |
| 新增項目 | 無回饋，直接返回 | inline 紅字 | 成功回饋不足 |
| 刪除行程 | 無回饋 | 無 | 缺少回饋 |
| 刪除項目 | 無回饋 | 無 | 缺少回饋 |
| 批量操作 | Event 有 `ShowBatchOperationResult` 但 UI 未處理 | 無 | 功能缺失 |

## 二、UX 改善建議（按影響程度排序）

### P0 — 阻斷性問題

#### P0-1: 刪除行程和產生路線按鈕無功能

**現狀**：`App.kt` 第 124-125 行
```kotlin
onDeleteItineraryClick = {},
onGenerateRouteClick = {},
```
使用者點擊「刪除行程」和「產生路線」毫無反應，嚴重影響信任感。

**建議**：
- 刪除行程：接上 `DeleteConfirmDialog` + 刪除後 `backStack` 返回列表
- 產生路線：接上 `CreateRouteFromItineraryUseCase` + 導航到 `RouteView`

#### P0-2: RouteView（路線檢視）匯出只有 println

**現狀**：`App.kt` 第 193 行（RouteView 路由）
```kotlin
onExportSuccess = { json -> println("Export JSON: $json") }
```

**建議**：使用平台分享功能（Android: Intent.ACTION_SEND、iOS: UIActivityViewController）

#### P0-3: 表單未儲存離開無確認

**現狀**：新增/編輯行程或項目時，按返回鍵直接離開，已輸入的資料全部遺失。
**檔案**：所有 AddEdit Screen

**建議**：
- 偵測表單是否有修改（dirty state）
- 有修改時顯示「確定要離開嗎？未儲存的變更將遺失」的確認 Dialog
- 新增模式已有草稿功能，可提示「已自動儲存為草稿」

---

### P1 — 高影響改善

#### P1-1: 新增行程按鈕改為標準 FAB

**現狀**：首頁的新增按鈕是 TopAppBar 右上角的小方形按鈕（32dp），顏色為 tertiary（深藍），容易被忽略。

**建議**：
- 改用 `FloatingActionButton` 放在右下角
- 顏色使用 `primaryContainer`，圖標用 `Icons.Default.Add`
- 符合 Material3 的 FAB 慣例，使用者直覺理解為「新增」

#### P1-2: 操作回饋（Snackbar）

**現狀**：刪除成功、儲存成功、批量操作完成都沒有任何 toast 或 snackbar。

**建議**：
- 在 `Scaffold` 中使用 `SnackbarHost`
- 刪除成功：「已刪除 XXX」+ undo 按鈕（特別是批量刪除）
- 儲存成功：「行程已儲存」短暫提示
- 批量標記完成：「已將 N 個項目標記完成」

#### P1-3: 新增項目表單分層

**現狀**：新增項目需要一次填寫 8 個欄位（活動、地點、地址、日期、到達時間、離開時間、照片、備註）。

**建議**：
- 將欄位分為「必填」和「選填」兩區
- 必填區（活動、地點、日期）放在上方
- 選填區（地址、時間、照片、備註）用 `ExpandableSection` 或灰色分隔區段
- 參考 Wanderlog 的「快速新增」：只需活動名稱 + 地點即可儲存

#### P1-4: 日期範圍未設定時的引導

**現狀**：新增項目時，若行程未設定日期範圍，日期欄位顯示 disabled + 「請先在行程中設定日期範圍」。使用者需要手動返回 → 編輯行程 → 設定日期 → 再回來新增項目。

**建議**：
- 提供「前往設定日期範圍」按鈕，直接導航到編輯行程頁
- 或允許在項目中手動輸入日期（不限於行程日期範圍內）

#### P1-5: 行程卡片增加更多資訊

**現狀**：行程列表卡片只顯示標題、日期範圍、建立日期，缺乏進度感。

**建議**：
- 顯示項目數量（如「5 個項目」）
- 顯示完成進度（如進度條或「3/5 完成」）
- 顯示主要地點列表（取前 2-3 個地點名稱）
- 參考 TripIt 的行程卡片設計

---

### P2 — 中等影響改善

#### P2-1: 時間軸導覽的互動優化

**現狀**：TimelineNavigator 提供日期選擇和快速新增，但日期節點較小。

**建議**：
- 日期節點顯示該日的項目數量 badge
- 點選日期後 LazyColumn 自動捲動到對應日期區段
- 當前日期（今天）有特殊高亮

#### P2-2: 行程項目拖拽排序

**現狀**：項目按日期分組顯示，同一天內的項目無法排序。

**建議**：
- 長按進入排序模式
- 支援拖拽重新排列同一天內的項目順序
- 參考 Funliday 的拖拽排序

#### P2-3: 地圖畫面增加路線連線

**現狀**：地圖只顯示標記點，沒有連線。

**建議**：
- 按日期顏色區分標記
- 同一天的標記用虛線連接，顯示移動路線
- 參考 Google Maps 的「我的地圖」功能

#### P2-4: 搜尋增加篩選條件

**現狀**：行程列表只有文字搜尋。

**建議**：
- 增加日期範圍篩選
- 增加地點篩選（曾去過的城市/國家）
- 增加完成狀態篩選（進行中 / 已完成 / 計劃中）

#### P2-5: 旅遊歷史增加統計摘要

**現狀**：旅遊歷史只是按地點分組的列表。

**建議**：
- 頂部增加統計卡片：「共去過 X 個地點，完成 Y 次旅行」
- 增加月曆視圖：可視化哪些日期有旅遊記錄
- 增加地圖總覽：所有去過的地點標記在同一張地圖上

---

### P3 — 體驗打磨

#### P3-1: 空狀態插圖

**現狀**：空狀態使用 Material Icon（Add icon 或 Place icon），較單調。

**建議**：
- 使用插圖（illustration）取代 icon
- 行程列表空狀態：旅行箱 / 地圖插圖 + 「規劃你的第一趟旅程」
- 旅遊歷史空狀態：相機 / 足跡插圖 + 「完成行程項目後會出現在這裡」

#### P3-2: 深色模式優化

**現狀**：有定義 DarkColorScheme，但部分元件的 dark mode 可能需要微調：
- `ItineraryDetailScreen` 使用 `isSystemInDarkTheme()` 手動判斷背景漸層
- `ItemCard` 也手動判斷 light/dark 處理 CompletedStateColors

**建議**：將 light/dark 判斷邏輯收到 Theme 層級，透過 CompositionLocal 提供。

#### P3-3: 手勢操作

**現狀**：
- 行程列表：長按出選單（編輯/刪除）
- 行程詳情：more menu 操作
- 沒有滑動手勢

**建議**：
- 行程卡片：左滑刪除、右滑編輯（SwipeToDismiss）
- 行程項目：左滑刪除、右滑標記完成
- 參考 iOS 原生列表的滑動操作

#### P3-4: 載入動畫

**現狀**：載入狀態只有 `CircularProgressIndicator`。

**建議**：
- 行程列表：使用 Shimmer/Skeleton 效果
- 行程詳情：按卡片形狀顯示 placeholder
- 提供更流暢的載入過渡體驗

## 三、競品 UX Pattern 參考

### 3.1 TripIt

| Pattern | 可借鏡之處 |
|---------|----------|
| 行程摘要卡片 | 在卡片上直接顯示航班、住宿、活動數量 |
| 時間軸視圖 | 垂直時間軸 + 每日行程摘要（TravelApp 已有類似設計） |
| 分享行程 | 一鍵分享行程連結 |
| 行程導入 | 轉寄 email 自動解析行程（進階功能） |

### 3.2 Wanderlog

| Pattern | 可借鏡之處 |
|---------|----------|
| 快速新增 | 只需輸入地點名稱，其他欄位自動填入或稍後補充 |
| 地圖 + 列表雙視圖 | 列表和地圖可快速切換，地圖標記點選直接顯示項目 |
| 預算追蹤 | 每個項目可選填花費，自動統計每日/整趟花費 |
| 行程範本 | 熱門城市提供預建行程模板 |
| 協作 | 邀請同行者共同編輯行程 |

### 3.3 Google Travel

| Pattern | 可借鏡之處 |
|---------|----------|
| 探索建議 | 根據目的地推薦景點、餐廳 |
| 自動整理 | Gmail 訂票資訊自動歸類到行程 |
| 離線存取 | 重要資訊自動下載供離線使用 |
| 極簡介面 | 首頁只顯示即將到來的行程，過去的行程收到「過往」tab |

### 3.4 建議優先導入的 Pattern

| 優先級 | Pattern | 參考來源 | 對應建議 |
|--------|---------|----------|----------|
| 高 | 快速新增 | Wanderlog | P1-3 |
| 高 | 操作回饋 | 所有 App | P1-2 |
| 中 | 行程進度顯示 | TripIt | P1-5 |
| 中 | 地圖路線連線 | Wanderlog | P2-3 |
| 中 | 統計摘要 | Google Travel | P2-5 |
| 低 | 滑動手勢 | iOS 原生 | P3-3 |
| 低 | Skeleton 載入 | 業界標準 | P3-4 |

## 四、摘要

| 優先級 | 問題數 | 關鍵改善 |
|--------|--------|----------|
| P0 | 3 | 修復空 lambda（刪除行程、產生路線、匯出）、未儲存離開確認 |
| P1 | 5 | FAB 新增按鈕、Snackbar 回饋、表單分層、日期引導、卡片資訊 |
| P2 | 5 | 時間軸優化、拖拽排序、地圖連線、搜尋篩選、歷史統計 |
| P3 | 4 | 空狀態插圖、深色模式、手勢操作、載入動畫 |

**最高 ROI 改善**：P0-1（修復空 lambda）+ P1-2（Snackbar 回饋）+ P0-3（離開確認）-- 這三項改善成本低但對使用者信任感影響最大。
